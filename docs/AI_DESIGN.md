# AI Design

Domain services depend on an `AiProvider` port, never directly on a vendor SDK. `AI_PROVIDER=local` selects the deterministic, explicitly labeled `LOCAL_TEMPLATE` fallback. `AI_PROVIDER=openai` selects the optional OpenAI-compatible Chat Completions adapter. It reads the API key from `AI_API_KEY`, bounds request and response sizes, times out, requests JSON output, validates the response, and never logs prompt content or credentials. Its request/response contract is tested against a local HTTP stub; a remote account/key has not been configured for this workspace. See `docs/AI_PROVIDER.md` for configuration and privacy details.

Core matching uses normalized skills and a versioned deterministic formula with evidence. Interview questions are seeded and evaluations identify their source. Current interview evaluation is only a local keyword-coverage heuristic and cannot judge technical correctness or run code. Provider API credentials are consumed only when the optional remote provider is explicitly selected. Uploaded resumes and job descriptions are untrusted data and cannot override system instructions.

Resume/cover-letter drafts use only supplied facts. Unsupported achievements are never invented; missing metrics are requested or marked as user-verification placeholders. Provider output is reviewed and edited by the user before any resume change is applied. Production AI use requires cost limits, abuse throttling, privacy disclosure, and retention controls.
